# Xtream series adapter — 2026-10-21

## Browser and playback continuation

The IPTV screen now exposes Series for a saved Xtream account. The full-size browser offers cached show search, 50-row paging, a season selector and numerically ordered episode pages. Refresh explicitly fetches either the show catalogue or the selected show's episodes using current encrypted account credentials. No eager request is made for every show's episodes. A failed request retains cached data and restores navigation. Long-press toggles an episode favorite. Selecting an episode closes the browser and sends that episode plus the rest of its current page to the existing shared player; playback resumes from saved progress.

Show/season/page/search state survives activity recreation; closing cancels network work and prevents stale UI callbacks. A closed browser is not restored. Valid account profiles with empty live/movie catalogues can now be imported, allowing Series to be used. All-invalid nonempty catalogues still fail; all-invalid series responses cannot erase the cache. Room remains v9.

## Storage continuation

Room v9 adds `iptv_series` and `iptv_series_episodes` with explicit v8-to-v9 migration and exported schema. Shows belong to playlists; membership links episode channels to shows with numeric season/episode ordering. Shared channel lookup remains usable by the player. Live/movie queries and whole-playlist refresh exclude episode members, preserving cached series during account refresh.

`IptvDao` provides paged searchable shows, season lists, paged episodes, and transactional show/episode replacement. Refresh retains favorites, playback mode and resume state, removes missing episodes/shows, and preserves unrelated live/movie channels. Invalid ownership, duplicate batches and collisions roll back. Playlist removal cascades through all series data; refresh cannot recreate a deleted parent. Series metadata refresh preserves the last episode-fetch timestamp. The adapter and storage are not yet connected to UI/network orchestration.

This is an implementation step toward series support, not a completed user-facing series feature. `XtreamSeries` fetches a series catalogue with one request and fetches episodes only for a selected show. The existing strict JSON reader, 4 MiB HTTP bound, cancellation and redirect rejection apply. Additional limits are 10,000 shows, 1,000 season groups and 10,000 episodes per show. Invalid catalogue/episode rows are counted and skipped; malformed response structure or exceeded limits fail the request.

Episodes sort numerically by season and episode number, including season zero specials. Episode channel references contain an opaque account ID and provider episode ID; credential resolution happens through the existing account resolver. Identity does not depend on password or container extension. IDs, extensions and season/episode values are validated. Provider-supplied direct-source URLs are not used. No schema change or automatic additional account-import requests are introduced.
