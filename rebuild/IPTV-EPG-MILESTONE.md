# IPTV XMLTV programme guide — 2026-10-13

Time-navigation continuation: the guide now opens with entries whose end is after the current time or whose start is at/after it. A programme ending exactly now is excluded; a missing end does not cause an already-started programme to be guessed as current. Show past programmes restores the complete imported schedule and survives recreation. Now / upcoming returns to page one with a fresh time filter. The cache update time is visible. Now labels are re-evaluated every 30 seconds while the dialog is open; unchanged labels avoid adapter updates and changed labels retain scroll position. The timer performs no network or database work and is removed on close. Membership of the displayed page is refreshed when navigating, toggling or selecting Now / upcoming; it does not move underneath a reader on every tick.

Use Programme guide on the IPTV screen, choose a channel from the displayed page, and enter an HTTP(S) XMLTV URL. One source is stored per playlist. Programme channel IDs match the M3U tvg-id, with no guessed name-based matching. The guide shows 50 entries per page in chronological order, local date/time and time-zone name, a Now marker for a known current interval, and a detail dialog containing the description. It includes past and future imported entries. A missing end time is shown as unknown and is not guessed. Guide page, source draft and selected channel survive activity recreation.

Import uses the bounded cancellable HTTP worker and reads gzip content encoding through the existing document client. XML and database work run off the UI thread. Bounds are 4 MiB per document, 10,000 programme entries, 32 XML levels, 500 characters per title/channel ID and 8,000 per description. A complete usable document is required before replacing the cached guide. Parse/network/storage errors preserve the previous transaction, and programme/source rows cascade when the parent playlist is removed. A late refresh cannot resurrect a removed playlist.

Room v7 adds epg_sources and epg_programmes with an index on playlist/channel/start time. Explicit migration 6–7 composes with versions 1–6. No destructive migration is used. Playlist channel refresh leaves its guide cache intact.

The parser follows the [XMLTV DTD](https://github.com/XMLTV/xmltv/blob/master/xmltv.dtd) for programme/channel association and timestamp structure. It accepts numeric offsets, UTC/GMT/Z and BST, and assumes UTC when omitted. Partial dates use the beginning of the specified period. Other named zones are rejected rather than guessed. It uses the first nonempty title/description, decodes XML text/CDATA, skips invalid/duplicate programmes, accepts an external SYSTEM DTD declaration without fetching it, and rejects internal subsets and unresolved entities. It does not claim full XMLTV compatibility.

The implementation also fixes an IPTV progress race: a checkpoint originating from a live media item is ignored even if its database playback override changes to on demand before that checkpoint is saved. Both the resolved playing-item policy and current stored policy must permit VOD progress.
