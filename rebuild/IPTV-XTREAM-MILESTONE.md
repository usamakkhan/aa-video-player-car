# Xtream live TV and movies — 2026-10-21

The IPTV screen now offers Xtream account sign-in using a playlist name, server base URL, username and password. It validates account authentication, active status and supplied expiry, then imports live channels and movies with category labels and EPG IDs. Imported entries use the existing paging/search/favorites, shared player, live/on-demand policy, fullscreen and guide UI. Playlist refresh uses the stored account. Signing in again with the same normalized base URL and username updates the account while retaining matching stream IDs, favorites and movie progress. Removing the playlist also removes its stored account.

Account credentials are encrypted with AES-GCM using an Android Keystore key and the account ID as authenticated data. Random IVs prevent equal plaintext from producing equal ciphertext. Credentials are not saved in the account dialog state. The database stores opaque xtream channel references; the service decrypts once per account per queue resolution and constructs HTTP(S) stream URLs in memory. Application account errors omit request URLs, credentials and underlying exception text. This is not a claim of exhaustive framework-log or memory secrecy. Keystore loss after reinstall/restore requires signing in again. User-entered M3U/XMLTV URLs retain their existing storage behavior; automatic authenticated Xtream guide import is not implemented.

The account client uses player_api.php authentication and live/movie category/catalogue actions, with live or movie stream paths. Account endpoints cannot redirect credential-bearing requests. HLS is preferred when advertised in allowed_output_formats, otherwise TS is used when supported; movie extensions come from an allowlist. API responses are limited to 4 MiB each, 32 JSON levels, 2,000 categories per kind and 10,000 total catalogue entries. Strict UTF-8 and JSON validation run before object parsing. Network, parsing, key and database work stays off the UI thread. Import is transactional: failures retain the existing account and channels. IDs distinguish live and movie entries even when their provider IDs overlap.

Room v8 adds xtream_accounts with a cascading playlist relation. The explicit v7–v8 migration composes with earlier migrations; schema 8 is exported. The v7 upgrade fixture retains guide data as well as channel favorites and progress.

References used to check the implementation: the [Xtream API client project's API examples](https://github.com/joefaron/xtream-js-api) and [Android Keystore documentation](https://developer.android.com/privacy-and-security/keystore). These are a compatibility reference and platform documentation, not evidence that every Xtream provider follows the same contract. No provider account or copyrighted stream service is bundled.

Xtream live playback is not independently established by the movie fixture; generic M3U HLS playback remains covered separately.

HTTP endpoints remain supported as explicitly entered; TLS depends on the provider URL. Limits above can reject larger catalogues.
